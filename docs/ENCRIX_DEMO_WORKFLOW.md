# ENCRIX Demo Workflow

## Launch

Run `npm run dev` from the repository, then visit `http://localhost:5173/demo`. For a client meeting, use the reviewed demo deployment only after the normal build/release approval process. The route is available from the landing page under **Try the Demo**.

## Walkthrough

1. Point out the persistent **DEMO MODE** banner and the synthetic-data boundary.
2. Review the overview totals, illustrative team activity chart, recent changes, and sample notifications.
3. Open **Leads**; search by name/ID/source and filter by status.
4. Add a sample lead with an `example.test` address, then edit or remove it. Deletion asks for confirmation and only affects the current page state.
5. Change a lead's status, assign/reassign it to a fictional telecaller, and record a sample interaction. Explain that this does not place a call.
6. Open **Follow-ups**, schedule a sample date/time, then mark a follow-up complete. Explain that no reminder email is sent.
7. Open **Team** and show the fictional telecaller roster and illustrative performance. Invitations are disabled in this public sandbox.
8. Open **Activity** and show the session-only timeline generated by your actions.
9. Explain the feature matrix and which production integrations remain pending verification.
10. Exit through **Exit demo**. Refreshing or leaving the route resets all actions.

## Demo safety checks

The page does not import AuthContext, database adapters, Supabase, API clients, or provider SDKs. `/demo` is routed outside the live AuthProvider. Client-side interactions mutate component state only. The `demo_workspace.test.tsx` test checks lead creation, assignment, interaction, follow-up schedule/complete and that `fetch` is not called.

Never enter real customer contacts, credentials, payment details, or confidential business information into this preview. Do not represent sample chart values or team performance as measured results.
